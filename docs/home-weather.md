# 首页天气光影

## 使用

后台“首页光影”现在包含六个时段和四个雨雪场景。雨雪场景分别有桌面横版和手机竖版；默认六时段行为保持兼容。三种运行方式：

- 随北京时间自动切换：原有六时段。
- 随时间与当地天气切换：雨、雪覆盖当前时段；其他天气沿用六时段。
- 固定一个主题：可选择全部十个主题，不需要天气服务。

晨光、日间、午后使用白昼雨雪；黄昏、夜晚、深夜使用入夜雨雪。这是随后台时段配置的昼夜划分，不是天文日出日落。天气模拟和图片预览无需 API 凭据。修改后使用现有“保存并部署”。

## 免费天气服务

现使用 Open-Meteo 免费非商业接口，无需注册、API Host 或密钥。后台可点击“测试连接”查询成都。默认运行方式为天气模式；已发布的运行方式仍以后台配置为准。旧 `QWEATHER_API_HOST` / `QWEATHER_API_KEY` 不再读取，无需维护。

天气使用 `https://api.open-meteo.com/v1/forecast`，仅查询当前温度及 WMO 天气代码；中文城市搜索使用 `https://geocoding-api.open-meteo.com/v1/search`。天气代码在服务端转换成中文和雨雪分类，图片无需变更。当前天气来自气象模型，不保证与窗外短时降水完全同步。保留 Open-Meteo 天气归因及 GeoNames 城市归因。参考：[天气文档](https://open-meteo.com/en/docs)、[城市搜索](https://open-meteo.com/en/docs/geocoding-api)。

服务失败、超时或限流时回退时段背景，五分钟后重试，不显示虚构温度或城市。原“随北京时间自动切换”和“固定一个主题”仍可使用，不请求天气。

## 定位与隐私

`edge-functions/api/weather/location.js` 使用 EdgeOne 原生 `request.eo.geo`，只返回中国大陆的大致城市和保留两位小数的坐标，不返回 IP，不请求浏览器精确定位。Node 本地开发、非大陆地区、缺失定位信息时返回空城市，访客可以手动选城。设置网站访问密码时，边缘定位返回空，统一使用受已有会话保护的手动选城接口。

手动城市和关闭偏好仅保存在本机 localStorage；天气缓存仅保存在当前标签页 sessionStorage（30 分钟）。自动定位依赖网络出口，VPN/代理或移动网络可能识别不准确。页面展示获取时间，不把缓存时间冒充气象观测时间；保留供应商归因文字/链接。

边缘定位返回英文城市名时，与天气查询并行调用已有城市搜索，将名称转换成邻近坐标对应的中文名称，天气仍使用原坐标。中文名称随天气一起缓存；查询失败时显示“所在城市”，不凭名称猜测其他城市。首页不显示裸域名，必需的来源链接以同行中文“数据来源”展示，完整署名和许可放在天气详情。

## 性能与额度边界

每个设备只加载当前场景的一张图片，四个天气场景共八个 WebP，单文件约 84–174 KiB。首次等待天气最多 500ms，标题和搜索不等待；超时先显示时段图，迟到结果只更新天气文字，下一次刷新或主动选城再切图。后续切换预加载成功才一起更新图文。

服务端按两位小数坐标/城市查询缓存 30 分钟，最多 512 项；相同请求合并，供应商请求 3 秒超时，失败冷却 60 秒，最多 8 个并发和每小时 120 次上游请求。所有前台天气响应不允许共享 CDN 缓存。

**免费服务仅适用于无广告、无收费的个人非商业项目。** 官方额度为每分钟 600 次、每小时 5,000 次、每天 10,000 次，并要求注明来源；不保证服务可用性。没有绑定付费接口，不会自动产生天气订阅费用。参考：[使用条款](https://open-meteo.com/en/terms)。

缓存和每小时 120 次预算只作用于单个运行实例，重启后重置，不代表全站总额度。多节点流量接近免费额度时应升级共享缓存/限流；达到限制会降级为时段背景。无需维护账号和密钥，但不能承诺第三方服务永远无需调整。没有额外数据库或依赖，也不批量抓取城市库。

## 验收边界

自动测试覆盖 WMO 代码映射、配置兼容、天气选择、缓存/预算、鉴权、输入校验、关闭偏好、慢响应和切城竞态。本地和线上可直接请求免费接口验收中文城市搜索及天气响应；返回数据不等于现场气象观测准确性证明。EdgeOne 城市识别可能受网络出口影响，多节点总额度也需根据实际流量另行评估；GitHub 同步不能替代线上验证。
