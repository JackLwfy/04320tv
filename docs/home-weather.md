# 首页天气光影

## 使用

后台“首页光影”现在包含六个时段和四个雨雪场景。雨雪场景分别有桌面横版和手机竖版；默认六时段行为保持兼容。三种运行方式：

- 随北京时间自动切换：原有六时段。
- 随时间与当地天气切换：雨、雪覆盖当前时段；其他天气沿用六时段。
- 固定一个主题：可选择全部十个主题，不需要天气服务。

晨光、日间、午后使用白昼雨雪；黄昏、夜晚、深夜使用入夜雨雪。这是随后台时段配置的昼夜划分，不是天文日出日落。天气模拟和图片预览无需 API 凭据。修改后使用现有“保存并部署”。

## 服务端配置

在 EdgeOne Pages 服务端环境变量中添加 `QWEATHER_API_HOST`（项目专属域名，如 `your-project.qweatherapi.com`，不含协议和路径）及 `QWEATHER_API_KEY`（和风天气 API Key）。这两个变量禁止使用 `NEXT_PUBLIC_` 前缀，禁止写入仓库或增量包。部署后在后台点击“测试连接”，再启用天气运行方式并保存部署。

使用和风天气新版 `/weather/v1/current/{latitude}/{longitude}` 和城市查询接口 `/geo/v2/city/lookup`。本版本采用 API Key 认证；供应商后续认证政策变化时需复核。参考：[实时天气](https://dev.qweather.com/docs/api/weather/weather-current/)、[城市查询](https://dev.qweather.com/docs/api/geoapi/city-lookup/)、[认证](https://dev.qweather.com/docs/configuration/authentication/)。

未配置凭据时不启用前台天气请求或入口，首页立即显示原有背景。配置存在但服务失败时回退时段背景，五分钟后重试，不显示虚构温度或城市。

## 定位与隐私

`edge-functions/api/weather/location.js` 使用 EdgeOne 原生 `request.eo.geo`，只返回中国大陆的大致城市和保留两位小数的坐标，不返回 IP，不请求浏览器精确定位。Node 本地开发、非大陆地区、缺失定位信息时返回空城市，访客可以手动选城。设置网站访问密码时，边缘定位返回空，统一使用受已有会话保护的手动选城接口。

手动城市和关闭偏好仅保存在本机 localStorage；天气缓存仅保存在当前标签页 sessionStorage（30 分钟）。自动定位依赖网络出口，VPN/代理或移动网络可能识别不准确。页面展示获取时间，不把缓存时间冒充气象观测时间；保留供应商归因文字/链接。

## 性能与额度边界

每个设备只加载当前场景的一张图片，四个天气场景共八个 WebP，单文件约 84–174 KiB。首次等待天气最多 500ms，标题和搜索不等待；超时先显示时段图，迟到结果只更新天气文字，下一次刷新或主动选城再切图。后续切换预加载成功才一起更新图文。

服务端按两位小数坐标/城市查询缓存 30 分钟，最多 512 项；相同请求合并，供应商请求 3 秒超时，失败冷却 60 秒，最多 8 个并发和每小时 120 次上游请求。所有前台天气响应不允许共享 CDN 缓存。

**缓存和预算只作用于单个运行实例，重启后重置，不是全站费用上限。** 多实例正式启用前，请在供应商控制台或网关设置总额度/预算告警。没有额外数据库或依赖，也不批量抓取城市库。

## 验收边界

自动测试覆盖配置兼容、天气选择、缓存/预算、鉴权、输入校验、关闭偏好、慢响应和切城竞态。本地浏览器可用模拟响应检查雨雪及双端图片加载。真实天气准确性、供应商账户额度、EdgeOne 城市定位和线上多节点缓存需要配置凭据并部署后单独验证；GitHub 同步不能替代这些验证。
